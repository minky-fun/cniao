## 当前小组件的 autologin 有原生依据

`MtopAutoLoginRequest -init`（0x1020dfa54）明确设置：

- API：`mtop.cainiao.cnmember.customer.autologin`（字符串引用 0x1020dfa8c）。
- 版本：`1.0`（0x1020dfa9c）。
- 模型 `AutoLoginRequest` 有 `refreshToken`、`accountId` 属性。

因此不能因发现另一套续期接口就判定现有 autologin 接口错误或必须替换。继续追踪 `LoginService +autoLogin:completion:`（0x10209c4cc）后，已确认在 0x10209c524 调用 toJSONDictionary，在 0x10209c544 转成 JSON 字符串，再在 0x10209c55c 调用 setAutoLoginRequest:。因此原生请求外层包含 autoLoginRequest 字符串，refreshToken/accountId 在该字符串内部。完整请求上下文与签名链路仍未还原。

## 另一条 CNLoginSDK 续期路径

已通过方法实现追踪下列调用链：

1. `CNLoginSDKLoginService -loginWithCNRefreshToken:`（0x1020c775c）读取全局 refreshToken，要求其为非空 NSString；本地无效时返回错误码 20003。
2. `CNLoginSDKQueryService -sendLoginWithRefreshToken:completion:`（0x1020b8790）创建 CNLoginSDKRefreshSessionIdRequest，设置 refreshToken 后发送。
3. 请求 `-init`（0x1020cb270）设置 API `mtop.cainiao.cboss.cnaccount.session.refresh`、版本 `1.0`。
4. 请求 `-assembleDictionary4Model`（0x1020cb2f8）加入 `refreshToken`；缺少时使用空字符串。其直接父类 CNLoginSDKBaseRequest 的同名方法仅执行 ret（0x1020c9960），没有额外业务字段。
5. `CNLoginSDKMTopNetworkService` 创建 MtopExtRequest，设置 API 和版本，调用 `useHttps`（0x10209af6c）、`useHttpPost`（0x10209af80）、`addBizParameters:`（0x10209afd4），最后通过 MtopService 发送（0x10209b084）。账号上下文与 isNeedEcode 也传入 MTOP。父类默认 isNeedEcode=false。

这里确认的是客户端业务参数与 MTOP 配置，尚未还原 MTOP 最终请求编码、主机选择和完整签名生成依赖。isNeedEcode=false 不等于无需签名或无需设备上下文。

## 响应与持久保存

`CNLoginSDKBaseResponse -parseInfo:`（0x1020d66cc）先读取根对象 data，再读取其中 errorCode、errorMessage、data。随后 CNLoginSDKRefreshSessionIdResponse（0x1020cb3f8）将内部 data 交给 CNLoginSDKLoginInfo。

所以该 SDK 路径读取的业务信息位于根响应的 `data.data`。LoginInfo 的初始化方法（0x1020be910）读取 refreshToken、sessionId、cnAccountId、employeeId、ext；没有据此推定每次服务端响应都会包含所有字段。

成功回调转入 `p_cnmemberLoginSucProcess:completion:`，在 0x1020c8f50 调用 saveLoginSuccessInfo:。后者（0x1020e3ee8）更新 sessionId 与 refreshToken，并通过 SecurityGuardManager 的动态存储组件写入：

- CNLOGIN_SDK_SESSION_ID_KEY。
- CNLOGIN_SDK_REFRESH_TOKEN_KEY。

对应加载方法位于 0x1020e423c。成功处理还包含 loginCookie 解析等状态同步。由此可见，App 的登录态管理包括凭据保存与其他状态更新。

## 续期失败后发生什么

续期错误回调在 0x1020c7938 调用 NSError 的 sessionOrRefreshTokenValid: 进行错误分类。命中相应分支后执行 doLogout:，并在 0x1020c79a0 转入 loginHavanaAndCNServer:；其他错误进入普通失败处理。成功则处理并保存新登录信息。

尚未反解该分类方法对应的具体服务端错误码，不能仅凭方法名解释其所有语义。也未确认普通菜鸟账号在运行时是否选择该 CNLoginSDK 路径；包内同时存在 cnmember autologin 和 cboss 续期实现。

## 对小组件的结论

后续修复保留现有业务 API、GET 方法及请求构造；更新了 Scripting 和 Loon 对内嵌 autoLoginRequest 的 token 轮换处理，详见自动续期修复说明.md。

原生证据支持成功续期后保存新凭据的设计，但不足以证明抓取一次旧签名就能长期调用另一 API。现有小组件已加入新 token 的本地持久保存与经包裹查询验证后的 sid 保存；本次静态分析没有验证它的真实服务端续期成功率。

尚需核对的关键部分是现有 cnmember autologin 的完整传输调用、MTOP 签名/设备上下文，以及实际账号响应。不能把新增 cboss API 直接换入现有流程，也不能承诺无限自动续期。

本报告仅对应 8.10.703 去广告样本，不能直接等同于此前 8.11.1008 的原生行为。本次使用本地 Mach-O/Objective-C 元数据和反汇编工具分析，没有调用 REA 服务。
