# 菜鸟小组件自动续期修复

本说明记录 2026-10-15 自动续期修复时的验证结果，对应 `scripts/cniao/widget.tsx` 和 `index.tsx`；当前实现以仓库源码为准。原有 GET 包裹 API、autologin API 及请求构造保留。

## 核心问题与修复

原生 LoginService +autoLogin:completion: 将 AutoLoginRequest 的 JSON 字符串写入 autoLoginRequest。refreshToken 和 accountId 位于该字符串内。此前更新外层 refreshToken 无法轮换原生封装内的 token。

- 组件与 Loon 都改为更新内层 refreshToken；已存在的扁平格式仍可使用。
- 迁移旧版误写到外层的本地 token，避免丢弃已轮换的新凭据。
- 成功续期后先保存轮换 token，再重试包裹请求；即使业务重试失败也保留新 token。
- 包裹重试成功后才保存新 sid，并绑定原始抓取头；App 重新抓取后不复用其他来源的 sid。
- 包裹接口返回非 JSON 的 HTTP 401/403 也会进入续期。
- 续期必须收到真正的 SUCCESS 返回码，不将 NOT_SUCCESS 等字符串误当成功。
- 组件分别提示缺少数据、续期拒绝、网络失败或续期后的业务请求失败，仅显示错误码，不输出服务端原始描述或凭据。

## 执行逻辑

读取当前包裹请求头 → 使用已验证并绑定该抓取头的 sid → 请求包裹 → 遇到 SESSION_EXPIRED 或 HTTP 401/403 → 读取本地最新 token（App 有新抓取时采用新抓取）→ 调用原有 autologin → 保存轮换 token → 用返回 sid 重试包裹 → 业务成功后保存 sid 供下一次组件刷新使用。

每轮只有一次 autologin，不无限重试。保留原有重新读取 BoxJS 的恢复步骤。

## 验证

TypeScript 编译、Loon JavaScript 语法检查及差异空白检查通过；18 项模拟回归测试通过。包含原生封装和扁平格式的连续两次过期、跨运行时持久化、非 JSON 401/403、旧缓存迁移、账号抓取变化、错误码及日志、Loon GET/POST 抓取与内嵌轮换。

正常包裹查询的 URL、方法和请求头已与修复前版本逐项对比一致。

没有使用真实账号发送认证请求；以上不代表已完成设备端或服务端真实续期验证。原有签名生成与传输方式未被替换，无法保证服务端永远接受旧签名或被撤销的 refreshToken。

## 使用

1. 将本地 Scripting 修改同步到手机 cniao 项目。
2. 更新 Loon 菜鸟抓取插件至 1.2.3，确保其远程 cainiao.js 已刷新。
3. 已有有效抓取可继续使用。若提示缺少续期抓取或服务端拒绝凭据，需打开菜鸟恢复登录态并重新抓取；仅刷新包裹列表不保证 App 一定触发 autologin。
4. 实际出现一次会话过期后，核对组件是否自行恢复；失败时组件会显示具体阶段及安全的错误码，无需提供 Cookie 或 token。
